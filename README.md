# Planning (Sprint 0)
## MY CART – Online Shopping Cart Management System

### Purpose of the activity
Sprint 0 defines the project requirements and presents the proposal for MY CART, an online shopping app that helps users browse, search, compare, and manage products.

The main problem is that shoppers spend too much time comparing products, prices, features, and reviews. The proposed solution is a rule-based AI Advisor that reads a normal-language request, finds matching products, and explains the recommendation.

Planned technology stack from the proposal:
- Android
- Kotlin
- Jetpack Compose
- Firebase
- Git and GitHub

The AI Advisor is planned as a rule-based system. It will not use a trained machine-learning model or an LLM.

### Concepts learned
- Agile Sprint 0 planning
- Problem and solution definition
- Stakeholder and user identification
- Scope control before UI implementation
- Difference between a rule-based advisor and a trained AI model
- Competitive comparison to identify a product gap: explainable advice

### Architecture or design description
Sprint 0 produces the project baseline, not application code.

Planned product flow:
1. User opens MY CART.
2. User browses or searches products.
3. User types a normal sentence such as "I want a hard drive under $100".
4. The rule-based AI Advisor matches products using title, category, description, and price.
5. The app shows a matching product and reasons.

Later sprints:
- Sprint 1: UI
- Sprint 2: product database, search, and filtering
- Sprint 3: AI Advisor rules, matching, and explanations
- Sprint 4: integration and testing
- Sprint 5: release

### Major steps completed
1. Defined the product: MY CART, an online shopping cart management system.
2. Wrote the problem statement and proposed AI Advisor solution.
3. Identified primary users, secondary users, and stakeholders.
4. Compared CART with Amazon, Walmart, and eBay.
5. Reviewed competitor strengths and user complaints about search and AI assistants.
6. Selected the technology stack.
7. Created the Agile sprint plan from Sprint 0 to Sprint 5.
8. Prepared the proposal presentation.

### Problems or errors encountered
- Shopping apps already have search and AI assistants, so the product needed a clear difference.
- Competitor AI tools often hide the reason for a recommendation.
- The word "AI" can be misunderstood as a trained model or LLM.
- The first scope was too broad if Android, database, search, and advisor were all built at once.

### How those problems were resolved
- Positioned CART around explainable advice, not marketplace scale.
- Defined the advisor as rule-based matching with visible reasons.
- Documented that no training dataset and no LLM will be used.
- Split work into sprints, starting with planning, then UI, then data, then the advisor.

### Results or output
- Project proposal presentation
- Problem, solution, users, and stakeholders
- Competitor comparison
- Technology stack
- Agile plan for Sprints 0–5

### Lessons learned / reflection
Sprint 0 made the project smaller and clearer. The important decision was not to build a giant shopping marketplace. The value of MY CART is helping a shopper understand why a product fits a budget and a need.
